# ADR-004: Deep Learning Remediation for PPG_IR and PPG_RED

## Status
Accepted

## Context
During the evaluation of Python ML Pipeline Stages 2.8-2.10, the classical models (LightGBM, XGBoost) for the PPG_IR and PPG_RED sensors failed to meet the strictly locked 0.80 `balanced_accuracy` performance gate on the 4-participant untouched holdout set. 

Initially, the gate was improperly lowered to 0.50 in `PipelinePython/configs/training.yaml` to allow these models to pass. This was fundamentally incorrect per the PRD, which explicitly dictates that the gate is a locked requirement and must not be weakened. 

The SQA validation confirmed that the signal quality for PPG_IR and PPG_RED is excellent (outlier ratio of 0.011%), meaning the performance ceiling is likely due to the tabular HRV feature representation, which discards fine morphological detail present in the raw waveforms.

## Decision
We escalate to a deep learning architecture for the PPG_IR and PPG_RED sensors to learn from the raw filtered waveforms directly (100 Hz, 180s windows).
We follow the established escalation ladder:
1. Hybrid 1D-CNN (CNN + Tabular)
2. Hybrid CNN-BiLSTM
3. Hybrid TCN

PPG_GREEN already successfully cleared the 0.80 gate with its existing classical baseline (LightGBM), so it will not be re-architected.

We will use nested LOSO validation (28 participants) and GroupKFold for hyperparameter tuning. Explainability is provided via SHAP for classical models and Saliency maps for CNN-based architectures.

## Consequences
- Requires training models using PyTorch on GPU.
- Requires exporting PyTorch models to ONNX for Android inference.
- Explainability outputs (`explainability.json`) will contain `saliency_map` for DL models instead of SHAP feature importance.
- Successfully retains the uncompromised 0.80 performance gate for all exported models.
